# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`graphlm` is a CLI + library that generates a codebase graph (Markdown + JSON + interactive HTML) from any project directory, using an OpenAI-compatible LLM plus deterministic Tree-sitter AST parsing. Python 3.11+, `uv`-managed, Pydantic v2, Typer CLI, `httpx` for the LLM call. No async — the LLM client is synchronous.

## Commands

```bash
uv sync --group dev                          # install (incl. pytest, pytest-cov, pytest-httpx, mypy)
uv sync --group dev --extra mcp              # + the optional MCP extra (needed for tests/test_mcp_server.py; skipped otherwise)
uv sync --group dev --extra js               # + JS/TS grammars (needed for tests/test_parser_javascript.py enabled-path tests; skipped otherwise)
uv sync --group dev --extra java             # + Java grammar (needed for tests/test_parser_java.py enabled-path tests; skipped otherwise)
uv sync --group dev --extra rust             # + Rust grammar (needed for tests/test_parser_rust.py enabled-path tests; skipped otherwise)
uv sync --group dev --extra csharp           # + C# grammar (needed for tests/test_parser_csharp.py enabled-path tests; skipped otherwise)
uv sync --group dev --extra cpp              # + C/C++ grammars (needed for tests/test_parser_cpp.py enabled-path tests; skipped otherwise)
uv sync --group dev --extra go               # + Go grammar (needed for tests/test_parser_go.py enabled-path tests; skipped otherwise)
uv sync --group dev --extra php              # + PHP grammar (needed for tests/test_parser_php.py enabled-path tests; skipped otherwise)
uv sync --group dev --extra typesafe         # + TypeSafe/Jev SDK (needed for tests/test_evidence.py — real Noul types; skipped otherwise)
uv sync --group dev --extra all              # every language pack (does NOT include mcp or typesafe)
uv run pytest -q                             # full suite (~1030 tests, ~6s, no network — LLM is mocked via pytest-httpx; language-pack + typesafe enabled-path tests skip without their extra)
uv run pytest tests/test_parser.py -q        # one file
uv run pytest tests/test_parser.py::test_name -q   # one test
uv run pytest --cov=graphlm --cov-report=term-missing   # coverage (CI reports it; ~90%, but NOT gated — no --cov-fail-under)
uv run mypy graphlm --ignore-missing-imports # type check (separate CI job; keep it clean)
graphlm /path/to/project --dry-run           # exercise scan + AST + context packing without any LLM call
```

CI (`.github/workflows/ci.yml`) runs pytest+coverage on Python 3.11/3.12/3.13 (base + `mcp` extra — language-pack and `typesafe` enabled-path tests skip), a separate `test-packs` job with `graphlm[all,mcp,typesafe]` on 3.12 (the enabled path — `--extra typesafe` so `tests/test_evidence.py`'s fake-client tests run in CI instead of skipping, #188), and mypy on 3.12. There is no linter/formatter configured — match surrounding style.

## Architecture — the big picture

The *analysis* pipeline lives in `graphlm/__init__.py::generate_graph()` — read that function first; it orchestrates everything below in order. (Output is separate: the library only writes when `output_dir` is set; the CLI leaves it `None` and writes itself — see below.)

**Two-pass LLM strategy** (the core design, to stay inside context windows):
1. **Pass 1** — `context.assemble_pass1_prompt(tree)` sends *only* the directory tree. The LLM returns `{"requested_files": [...]}` — the files it wants to read. The tree is size-bounded by **two** caps in `scan_project` so this prompt stays within context on a huge repo: (a) a *per-directory* cap of `max_tree_entries_per_dir` listed children (default 200 via `_MAX_TREE_ENTRIES_PER_DIR`), emitting a "… N more entries not shown" marker past that — per-directory rather than global so deeply nested source stays visible instead of being crowded out by an early cache dir; and (b) an absolute *total-lines* ceiling of `200 × _TREE_TOTAL_LINE_MULTIPLIER` (= 5000 lines) that stops the whole walk (the per-dir cap alone is only `per_dir × num_dirs`, so a repo with thousands of dirs still needs the total backstop). Each tree line is `indent + basename` (directories end with `/`); restating the full relative path on every line made the 5000-line cap still overflow `max_context` on deep monorepos (n8n's tree was ~151k tokens and zeroed the pass-2 edge budget, #69). Pass 1 is told to reconstruct full relative paths from the indent when requesting files. Both caps bound tree text only, not which files are read (`max_files`). Unlike pass 2, pass 1 has **no token-budget enforcement** — these caps plus `_ALWAYS_EXCLUDE` are what keep it in bounds. `_ALWAYS_EXCLUDE` also blocks graphlm's *own* output so a re-run over an already-mapped project never ingests its own map/diff as source: the CLI default output dir **`.graphlm/`** is excluded as a whole directory (`_should_exclude` matches any path component), and — for the case where output is redirected into the scanned tree with `-o` — the artifact *filenames* (`GRAPH.md`/`.json`/`.html`, `GRAPH_DIFF.md`/`.json`) are also excluded by exact name, not a `GRAPH*` glob, so a user's `GRAPHICS.md` survives (#28).
2. **Pass 2** — `context.filter_requested_files()` maps those back to scanned fragments (exact path after `./` normalisation, then `/`-suffix so `cli.py` finds `app/cli.py` and not `tests/test_cli.py`, then a repo-prefixed request — never substring containment, so `a.py` cannot select `data.py`, #85; `max_files` keeps pass-1 request order then sorts the kept set, #98), then `assemble_pass2_prompt()` assembles tree + file contents + the AST-edge table + the instruction block, and asks for the full `CodebaseGraph` JSON. The *input* token budget is enforced: the tree, edge table, instruction block, and a small message-overhead reserve (`MESSAGE_OVERHEAD_TOKENS`, for the system prompt + framing) are counted up front, and files are admitted only until the running total would exceed `max_context` (over-budget files land in `truncated_paths`). So the assembled prompt stays within `max_context`. If the tree already fills that budget, the edge table is omitted from the prompt and the warning names the tree overflow (parser edges still reach the graph and cycle detection — never "header does not fit the 0-token edge budget", #69). The **output** budget (`max_tokens`) is *not* reserved out of `max_context` — input and output ceilings are independent on the target endpoint (#25). **The model is told to return an empty `directory_tree`** — `generate_graph` fills `graph.directory_tree = scan.tree` locally afterward (alongside the `deterministic_edges` fill), because echoing a large tree back as output alone can blow the output-token ceiling and truncate the graph (#18). So don't reintroduce a "include the tree" instruction.

`--dry-run` skips both LLM calls. It does *not* model "all scanned files" — it selects `scan.file_fragments[:max_pass2_files]` (default cap 80), builds a `CodebaseGraph` carrying the AST edges + cycles + a dry-run note, and the CLI prints token estimates (`pass1_tokens` is `estimate_tokens(assemble_pass1_prompt(tree)) + MESSAGE_OVERHEAD_TOKENS`, the same accounting as pass 2 — not a stub of the instructions plus the raw tree, #86), the **AST import-edge count** (`AST import edges: N`, or `AST off` — read from `deterministic_edges`, *not* the LLM's `import_edges`, which a dry run never fills and so always read `0`), and graph-section counts. Tokens are estimated by a crude heuristic — `estimate_tokens` = `UTF-8 bytes * 2 // 5` (≈2.5 bytes/token). It is defined once in `scanner.py` and re-exported by `context.py`. The ratio is calibrated to over-estimate: real content measured ~2.83 bytes/token against the served model, so the old `// 4` (4 bytes/token) *under*-counted by ~28% and let graphlm pack prompts the model then rejected or timed out on — the `* 2 // 5` divisor sits safely above the real count (#17).

**AST parser is ground truth, not a replacement for the LLM** (the `graphlm/parsers/` package — `base.py` is the registry-driven Tree-sitter backend + language-agnostic dispatch, `python.py` is the Python resolver; `graphlm/parser.py` is a thin backwards-compat shim re-exporting the public contract, incl. `_source_roots`; on by default, `--no-ast` disables). `build_dependency_graph()` extracts Python import edges with Tree-sitter and resolves them *only against files that exist in the scan* (stdlib/third-party/missing modules are dropped — resolution is against the `known_files` set, independent of `project_dir`). Because edges resolve only between *scanned* files, the scanner's `_rank_file` ranks source code (`_SOURCE_EXTS`) above non-source text so a doc-heavy repo can't crowd source out of the `max_files` cap and starve the graph (#19). Resolution handles **src-layout** projects: `_source_roots()` accepts a source-root prefix only when its final segment is a conventional root name (`_SOURCE_ROOT_NAMES` = `src`/`lib`/`python`) that directly contains a package, and each import candidate is tried under every accepted root (root `""` first, so root-layout projects are unchanged) — without this, a `from mypkg.x import Y` in a `src/mypkg/` project resolved to nothing and the whole AST graph came back empty (#19). The allowlist is deliberate: deriving a root from *any* directory containing an `__init__.py` let a `tests/stub/requests/__init__.py` shadow make third-party `import requests` resolve to a project-internal file — a false edge in the "do-not-contradict" ground-truth table, worse than a missing one. A conventional `src`/`lib`/`python` nested under `tests/`/`vendor`/`stubs` is also rejected (#161). `project_dir` is *optional*: given, `_source_bytes` reads the untruncated/unredacted file off disk; omitted, it falls back to the (truncated) `frag.content`. Those `deterministic_edges` are (a) injected into the pass-2 prompt as a "do not contradict" table, and (b) used for cycle detection instead of the LLM's edges. The two uses diverge under a tight `max_context`: the **prompt** copy of the table is capped at a share of the budget (`EDGE_SHARE`, `context.py`) and, when capped, its framing flips to "not exhaustive — infer the rest" so a partial list isn't presented as complete; the **full** list always reaches `graph.deterministic_edges` and cycle detection. So the LLM's `import_edges` and the AST's `deterministic_edges` are separate fields on `CodebaseGraph` and can differ. **Python is the only core language** (the sole grammar in the base install). JS/TS import edges are extracted by `parsers/javascript.py` when the optional `graphlm[js]` extra is installed (`tree-sitter-javascript` + `tree-sitter-typescript`); without it, JS/TS files contribute zero edges and one log line per language, never a crash, and Python edges stay intact (`deterministic_edges` stays a list — a missing pack must never look like `ast=False`). Resolution is relative specifiers only (`./foo`, `../bar`) with extension-probe `<spec>`, `<spec>.{ext}`, `<spec>/index.{ext}` — `.js` importers prefer `.js/.jsx/.mjs/.cjs` then `.ts/.tsx`, `.ts` importers the reverse; bare specifiers (`react`) are dropped like Python stdlib. A dropped bare specifier marks the language known-partial so the pass-2 edge table flips to the non-exhaustive framing even when it was not size-capped. `kind` is `import` for import/export-from/dynamic `import()`, `require` for `require()` and TS `import x = require(…)` — `(from,to,kind)` is the diff identity contract (ADR-004). `.tsx` uses `language_tsx()` (grammar selection is by file suffix, because `detect_language` maps both `.ts` and `.tsx` to `"typescript"`). JS/TS `source_roots()` is grammar-free and returns `("",)` — relative paths resolve from the importing file, not a source-root prefix. The JS/TS resolver must let `_GrammarUnavailable` propagate (re-raise before a generic `except Exception`) so the once-per-language warning fires; python.py does the same. Java (`parsers/java.py`, extra `graphlm[java]`) is FQN→file: `import com.acme.User` → `<root>/com/acme/User.java` under Maven roots `src/main/java` / `src/test/java` (and a bare `src/`), with the file's `package` declaration as a disambiguator. `kind` is `import` for a type import and `static` for `import static` (ADR-005). Package wildcards (`import pkg.*;`) are dropped — they would fan out to every `.java` in the package and churn GRAPH_DIFF when a file is added — and mark the language known-partial; `import static Type.*;` still resolves to `Type.java`. Nested types try `Foo/Bar.java` then `Foo.java`. `source_roots()` is grammar-free. Same re-raise / once-per-language degradation as JS/TS. Rust (`parsers/rust.py`, extra `graphlm[rust]`) is two-step: `mod foo;` is kind `include` to `foo.rs`/`foo/mod.rs`; `use crate::`/`super::`/`self::` resolve against a filesystem module tree from the scan (`lib.rs`/`main.rs` crate roots). External crates are dropped. Inline `mod { … }` and `#[path = "..."]` modules are skipped and mark the language known-partial (ADR-006); `#[cfg(feature = "path")]` is not a path attribute (#153). C# (`parsers/csharp.py`, extra `graphlm[csharp]`) maps `using static Ns.Type` / `using Alias = Ns.Type` to `Ns/Type.cs` (then `Ns.cs` for a nested type); a namespace `using Ns;` resolves only when exactly one scanned `.cs` lives in that namespace directory — two or more files are a policy drop (GRAPH_DIFF fan-out, ADR-007) and mark known-partial; the nested-type parent-file probe is not applied to namespace usings, so `using MyApp.Models` does not resolve onto `MyApp.cs` (#126); a `using Alias = MyApp.Models` namespace alias unique-dirs first and only parent-probes on a miss (#134); `using System;` / Microsoft / Windows BCL roots never unique-dir-resolve, even if a lone `System/Console.cs` is scanned (#100); other misses are third-party, not partial. C/C++ (`parsers/cpp.py`, extra `graphlm[cpp]`) maps quoted `#include "foo.h"` relative to the importer as that exact name (kind `include`), including includes nested under `#ifdef` (#99); an extension probe (`.h`/`.c`/`.hpp`/…) runs only for extensionless `#include "foo"`, so `"foo.h"` does not hit a sibling `foo.c` (#128); angle-bracket system headers are dropped; macro includes mark known-partial (ADR-008). `.c`/`.h` use the C grammar, `.cpp`/`.hpp`/`.cc`/… the C++ grammar. Go (`parsers/go.py`, extra `graphlm[go]`) maps `import "mod/pkg"` to a unique non-test `.go` in that package directory (suffix-stripped so a module prefix is optional); multi-file packages are a policy drop (ADR-010); `import "./rel"` is path-relative; specifiers with no `.` (`fmt`, `encoding/json`) are stdlib and never resolve, even onto a unique local `fmt/` directory (#95). PHP (`parsers/php.py`, extra `graphlm[php]`) maps `use App\Models\User` to `App/Models/User.php` and quoted `require`/`include` relative to the importer (kind `include`), including `require 'x.php' or die()` (#135); interpolated `"config.php$id"` is a policy drop (#147); the parent-file probe is only for `use function` / `use const`, so a class `use` does not resolve onto `Models.php` (#129); concatenated `__DIR__` paths mark known-partial (ADR-011). Grammar accessor is `language_php`.

**Oversized files are skeletonised, not head-truncated.** In `scan_project`'s read loop a file longer than `max_file_chars` (default 4000) is handed to `parsers.base.skeleton_for(path, bytes)`; for Python that returns `parsers.python.skeleton()` — the module docstring head, imports verbatim (incl. under a top-level `try:`/`if TYPE_CHECKING:`), every class/def header with decorators and multi-line signatures intact, each docstring's first line, class attributes and constants that fit in two lines (`NAME = {…}  # N lines elided` otherwise), and `if __name__ == "__main__":` reduced to its header; bodies become `...` and the first line is `# [graphlm skeleton: bodies elided; N source lines]`, which `context._build_instruction_block` explains to the model ("signatures exact, don't invent behaviour for elided bodies"). Only if the skeleton is *still* over the cap, or `skeleton_for` returns `None` (no language / no resolver / `_Resolver.skeleton is None` / grammar pack missing / renderer exception — it never raises), does the old head slice apply. Order in the loop is load-bearing: read → `line_count` capture → skeleton-or-truncate → `_redact_secrets` — redaction must run on the *final* text because docstring first lines and short constants survive into the skeleton. `skeleton_for` is imported *inside* `scan_project` (function-local) because `parsers/base.py` imports `FileFragment` from `scanner.py` at module scope — a top-level import would be a cycle. `--no-skeleton` / `scan_project(skeleton=False)` / `generate_graph(skeleton=False)` restores head-truncation. Python only; other languages still head-truncate. **The renderer derives columns and row spans from byte offsets (`_col`/`_rows`), never from `Node.start_point`/`end_point`** — with py-tree-sitter 0.26.0 those corrupted the heap on a full-tree walk (ASLR-dependent segfault in `_PyObject_Malloc`, reproduced 12/12 by a deep `.children` walk that read points and 0/12 by the same walk on byte offsets); `tests/test_skeleton.py` guards the skeleton section against reintroducing them and skeletonises every module in the repo in-process.

**Cycle detection** (`cycles.py`) runs Tarjan SCC over the AST edges (falling back to LLM edges if AST is off), scoring each cycle `log10(total_lines) * cycle_length`. Edge paths and sloc-map keys are normalised (leading `./` stripped, backslashes folded) before lookup so an LLM `./a.py` still hits the scanned `a.py` — without that, `--no-ast` risk scores collapsed to 0 (#84). The SLOC term is `FileFragment.line_count` — the *on-disk* physical line count (newlines + 1, including blanks/comments), captured in `scan_project` **before** any truncation/skeletonisation, so a large file in a cycle is weighed by its real size, not by the `max_file_chars` slice (it previously counted the truncated content and under-weighted exactly the files that matter most). It is still not true source-lines-of-code. `FileFragment(..., line_count=None)` falls back to counting `content` for hand-built fragments. Also: `graphlm/parsers/base.py` *also* has its own `detect_import_cycles()` (returns bare node lists, no scores; re-exported via the `graphlm/parser.py` shim) — the live path uses `cycles.detect_cycles()`; don't confuse the two.

**Data models** (`models.py`) — `CodebaseGraph` is the Pydantic schema the LLM must emit and the single source of truth for output shape. `Cycle` is a frozen dataclass (not Pydantic). The pass-2 prompt in `context.py` hand-writes the JSON schema description for the LLM; **if you add/rename a field on `CodebaseGraph`, update that prompt text and `render.py` in the same change** — they are not auto-derived from the model. **Exception — `meta` (`GraphMeta`):** the provenance stamp is *not* LLM-emitted (like `directory_tree`/`deterministic_edges`, it's filled locally in `generate_graph`), so it is deliberately **not** in the pass-2 instruction block — don't add it. Its `schema_version` (`GRAPH_META_SCHEMA_VERSION`) is a versioned *input* contract: graphlm reads its own prior `GRAPH.json` for the fast-follow diff, so bump it if the meta shape changes (see the self-refreshing-graph ADR in `DECISIONS.md`).

**Output** (`render.py`) — writes `GRAPH.md` and (by default) `GRAPH.html` + `GRAPH_DIFF.md`, plus an always-written internal JSON working copy `.graph-state.json` (`freshness.STATE_FILENAME`, the diff baseline + `--serve` map). The user-facing `GRAPH.json` and `GRAPH_DIFF.json` are **opt-in** — `write_outputs(json=...)` / `GraphResult.write(include_json=...)`, default `True` for library callers, but the **CLI defaults it off** (`--json` to enable) since the `.md` is the agent-facing map. `render_markdown` opens with a `## Orientation` block (`orientation.py`, between the header and `## Directory Tree`) and groups test-only import cycles under `## Import Cycles` (`cycles_render.py`). **Fresh-run cleanup** (`freshness.py`): a re-run removes graphlm's *own* stale artifacts (exact names only, symlinks skipped, gated on `owns_dir` so a fresh user dir is never touched); a prior map from a different graphlm version yields a `VERSION_CHANGED` diff. The `*_suffix` params default to `"GRAPH"`. **`GRAPH.md` carries a Mermaid `## Module Graph`** (`mermaid.py::render_mermaid`, called from `render_markdown` right after the directory tree) — GitHub renders Mermaid natively, so the Markdown map has a picture with no CDN. It is a **directory-level** `flowchart LR` (files collapse to their parent dir via `_collapse_dir`; a root-level file stays its own node), deduped, self-edges dropped, capped at `max_nodes=40` by (in+out) degree with a "… N more directories not shown" note past the cap. Edge source is `deterministic_edges` when non-empty (note says "ground truth"), else the LLM `import_edges` ("inferred"); `[]` when neither. Cycle styling: paths are `./`-stripped before collapse/membership so LLM `./a.py` does not become a `.` node or miss the red ring (#96); a collapsed edge is a cycle edge when its *file-level* endpoints share an `import_cycles[].nodes` set — those are emitted **last** so their `linkStyle` indices are the tail of the link list (Mermaid styles links by emission index, nothing else) — and any directory containing a cycle member gets a `style … stroke` outline (red `#e11` for a production cycle, muted amber `#b8860b` `TEST_CYCLE_COLOR` when the dir's only cycle is test-only — production wins when a dir has both), because an intra-package cycle (the common case) collapses to a dropped self-edge and would otherwise leave no trace. A directory whose edges are *all* self-edges is still a node (single-package projects — the `cyclic_project` fixture — otherwise rendered an empty block). Ids are `n_` + `[^A-Za-z0-9_]→_` with a numeric suffix on collision; labels are quoted with `"`→`#quot;`. Everything is sorted for stable diffs. HTML (`html_render.py` + `_html_template.html`) is a single self-contained *file* (string-substituted, no build step) — but it loads D3 from a CDN (`_html_template.html` → `https://d3js.org/d3.v7.min.js`), so the graph won't render offline. HTML is on by default; `--no-html` / `include_html=False` skips it. **The HTML draws ground truth as layers:** `_build_links` emits `deterministic_edges` as `type: "ast"` links (solid `#7aa2f7`, one per `(from, to)` pair even if the parser produced several), drops any LLM `import_edges` entry with the same `(from, to)` and marks the AST link `corroborated: true` (one pair, one line), and keeps LLM-only imports as grey `type: "import"`; `_build_nodes` upserts AST endpoints too (D3 forceLink throws on a missing id) and sets `in_cycle` on every node from `import_cycles`. The embedded JSON is `{nodes, links, cycles, provenance}` (`cycles` = SCC count for the stats line; `provenance` = version/commit/date, machine-readable, not shown in the UI; each node also carries `is_test` and `in_cycle`), spliced via `_json_for_script` so a `</script>` in a path cannot close the inline `<script>` tag. The template rings `in_cycle` nodes red (`#e11`, 2.5px — via `nodeStroke*` helpers so the hover restore keeps the ring), has a Layers control (checkboxes `data-layer="ast|import|data_flow"`) that toggles links with CSS `display` only (never touches the simulation), and legend/stats entries for the new layer. `write_outputs` computes every path it will write and refuses a symlink at **all** of them (output dir, `GRAPH.md`, working copy, and whichever of `GRAPH.json`/`.html`/`GRAPH_DIFF.*` this run produces) **up front — before any cleanup deletes or any file is written** (same contract as skill install, #33), so a symlinked HTML can't let cleanup remove a stale JSON and leave a half-written dir. `Path.write_*` would otherwise follow the link and clobber a file graphlm did not create. **`write_outputs` returns a `WriteResult`** — a `tuple` subclass that *is* the `(md, json, html)` 3-tuple existing callers unpack (so `md, json_, html = write_outputs(...)` still works), with `.diff_md` / `.diff_json` attributes carrying the diff paths (`None` when `diff=False`). ADR-002 requires the arity stay 3 for the ~10 positional-unpack sites; don't turn `WriteResult` into a 4-/5-field tuple. `WriteResult.__new__` accepts *either* three positional path args *or* a single 3-sequence, and it defines `__getnewargs_ex__`, so `copy`/`deepcopy`/`pickle` round-trip it with `.diff_md`/`.diff_json` intact (a bare tuple subclass loses them). Note `==` still ignores the diff attrs (inherent to the tuple-subclass choice) — that's accepted.

**Graph-vs-graph diff** (`diff.py` + the `GRAPH_DIFF.*` outputs; on by default, `--no-diff` / `include_diff=False` disables). The diff runs **in `write_outputs`, not `generate_graph`** (ADR-002 decision 1) — it's the only place holding both the graph and the output dir (the CLI passes `output_dir=None` into `generate_graph`, the #8 split). Ordering is load-bearing: `freshness.prepare_baseline()` reads the *prior* graph **before** the working copy is overwritten, in **source order** — the internal working copy `.graph-state.json`, else (first post-upgrade run, no working copy yet) the prior `{json_suffix}.json` — via `load_baseline()`, which **never raises** (it runs on the write path *after* the paid LLM call, so an escaping exception would abort the run and discard the new graph). It classifies **four states** that must never collapse (decision 4, amended by ADR-016): `FIRST_RUN` (file genuinely absent — a *broken symlink* is `UNCOMPARABLE`, not first-run), `UNCOMPARABLE` (anything that can't be safely interpreted: corrupt/truncated JSON, bad encoding — `render_json` writes `ensure_ascii=False`, so a killed/disk-full prior run can leave a mid-codepoint file, and `UnicodeDecodeError` is a `ValueError` not `OSError` — *or* an unrecognized `meta.schema_version`, checked against `_KNOWN_META_SCHEMA_VERSIONS` *before* model validation, with a `bool`-and-`int` type guard so `schema_version: true` doesn't sneak through as `1`), `VERSION_CHANGED` (a NORMAL baseline whose `meta.graphlm_version` differs from this run's — regenerated fresh, not compared; names both versions), and `NORMAL`. The read+parse and the validate are each wrapped in a broad `except Exception` → `UNCOMPARABLE` (deliberately broad: the contract is "cannot read → uncomparable", not "cannot read in one of a few specific ways"). An old, meta-*less* `GRAPH.json` parses fine (`meta=None`) and compares as `NORMAL` with an `unknown` old SHA — only corrupt/unknown-version files are uncomparable. `compute_diff` is **added/removed only, no "changed" bucket** (decision 2): identity keys are structural (`modules`→`path`; edges→`(from,to,kind)`; `import_cycles`→`frozenset(nodes)`; `data_flow`→`(source,destination)`; `entry_points`→`(path,name)`; `file_summaries`→`path`), so a pure prose rewrite is invisible by design. Those keys **are the diff's contract** (decision 3) — changing one changes what counts as "the same entity". Renames are remove+add (no rename heuristics — locked). **`deterministic_edges` None-vs-`[]` is honored** (decision 5): if either side is `None` (AST off on one run) the AST dimension is `compared=False` ("not compared"), never a mass deletion. The "no structural changes" banner in the `.md` is gated on `GraphDiff.all_compared` — if a dimension was skipped it flips to "no changes *in the compared dimensions*", so a not-compared dimension is never read as unchanged (the same non-collapse rule as decisions 4/5, at the render layer). The `GRAPH_DIFF.json` carries its own `DIFF_SCHEMA_VERSION` (**2** — bumped for the `VERSION_CHANGED` state + `old_graphlm_version`/`new_graphlm_version` fields; independent of the graph's `GRAPH_META_SCHEMA_VERSION`), the state label, the old→new SHA range (a `null` side reads `unknown`), the two graphlm versions, and per-dimension added/removed lists. The diff *Markdown* rides `--no-diff`; the diff *JSON* also rides `--json` (it's a machine-readable deliverable). Output filenames follow the `*_suffix` convention: **`diff_suffix` defaults to `None` and resolves to `json_suffix`** (decision 6 — the diff tracks the graph's suffix, so `json_suffix="map"` → `map_DIFF.*`, read from and written beside `map.json`); pass `diff_suffix` to override. **`--dry-run` writes no diff** — the dry-run branch in `generate_graph` returns *before* any `write_outputs` call, and the CLI exits before `result.write` (both correct, intended; don't "fix"). No new network or LLM call — pure local computation. See ADR-002 in `DECISIONS.md`.

**Self-refreshing stamp** (`provenance.py` + the `meta` field). `provenance.py` is the *only* module that reads git / shells out — `git_commit_sha()` runs `git rev-parse HEAD` (argv list, no shell, `cwd=project`, failure-tolerant → `None`; a SHA is accepted only on exit 0 **and** a 40/64-hex match, which rejects the empty-repo literal `HEAD`). `generate_graph` fills `graph.meta = GraphMeta(...)` locally after pass 2 **and** in the `--dry-run` branch, overwriting any LLM-emitted `meta`. `render.py` then (a) renders a top-of-`GRAPH.md` **refresh directive** in two forms — *git form* (SHA present: "generated by graphlm `<version>` against commit `<sha8>`… compare `git rev-parse HEAD`… regenerate with `graphlm .`"; the "by graphlm X" prefix is dropped when `meta.graphlm_version` is `None`) and *non-git form* (SHA `None`: "regenerate when you believe the code changed") — and no directive at all when `meta is None` (old/library graphs); and (b) preserves `commit_sha: null` in `GRAPH.json` by re-splicing `meta` (the module-wide `exclude_none=True` would otherwise drop it, making non-git indistinguishable from old-format). Wording is "generated against", never "reflects" (dirty-tree honesty). See `docs/plans/self-refreshing-graph.md` and the ADR in `DECISIONS.md`. **`meta` also carries run telemetry** (innovation #6), filled locally in the same place after pass 2 and *not* on a dry run: `usage` (`RunUsage` → per-pass `PassUsage` with the endpoint's real `prompt_tokens`/`completion_tokens` — from the `on_usage` callback `call_llm` fires when the response carried a `usage` object — beside graphlm's own `estimated_prompt_tokens` for that prompt, so the `estimate_tokens` ratio is auditable from the stamp) and `faithfulness` (`faithfulness.py::score` — the LLM's `import_edges` vs the AST `deterministic_edges` on `(from,to)` pairs, kind ignored, LLM side restricted to kinds `import`/`from`/`require`/`static`/`include` and to extensions the AST actually emitted (`.py` always; `.js`/`.jsx`/`.ts`/`.tsx` when `[js]` produced those edges; `.java` when `[java]` did; `.rs` when `[rust]` did) — that's all the parser can confirm; `None` when AST is off — "not scored" must never read as "scored zero"). Both are **additive optional fields, so `GRAPH_META_SCHEMA_VERSION` stays 1** (ADR-001 bumps only on a meaning change; an old `GRAPH.json` without them loads as `NORMAL`). `telemetry_render.py` (`render_telemetry` + the per-metric `usage_summary`/`faithfulness_summary`/`evidence_summary`, split out of `render.py`) renders them as one `> **Run telemetry.**` line directly under the directive, called from `render_markdown`; the CLI reuses the same summaries for its `Usage:`/`Faithfulness:`/`Evidence:` lines so the wording is single-sourced; each part is omitted when unmeasured and the line is dropped when none is.

**`meta.evidence_support`** (`evidence.py` + the `typesafe` extra) is the third telemetry field, scoring the LLM's *prose* the way `faithfulness` scores its *edges* — and, like both above, it is additive-optional (schema stays 1), filled locally after pass 2, **never** on a dry run, and **never** in the pass-2 instruction block (it is not LLM-emitted). Each `file_summary` is scored by a TypeSafe/Jev **SOFT Noul** ("does the CLAIM correctly identify the file's role and the symbols it defines? minor unverifiable detail acceptable; a wrong role or invented symbol is not") against the **`pass2_files` `frag.content`** — the redacted/skeletonised/truncated text the model actually saw, **never** disk bytes or `parsers._source_bytes` (that would be an unredacted third-party leak, and would score the *file* rather than the *evidence the model had*). A summary is **skipped** (`EvidenceSupport.skipped`, not scored) when there is no evidence to compare against: its file was not in pass 2 (never scored against content the model never received), **or** its source is under `_MIN_EVIDENCE_CHARS` (64) stripped bytes — a near-empty `__init__.py` / thin entry point defines nothing, so the support Noul has no signal and returned a meaningless ~0.2 that falsely flagged correct minimal summaries as weak (#168; `tetris.py`'s 72-char import+guard still scores). Questions batch ~15/request (discriminator in the Noul `instructions` over a shared `state`). It is a **trust weight, not a hallucination accusation**: a skeletonised fragment legitimately lowers the score, and the field exposes per-file low outliers (`low: list[FileScore]`) plus `mean`/`scored`/`skipped`, mirroring how `Faithfulness` exposes `matched`/`llm_edges`/`ast_edges`. `evidence.score` **never raises** (best-effort, runs after the paid call), and `generate_graph` wraps the fill in a second `try/except` for defence in depth — a scorer failure leaves the field `None`, never discards the graph. It returns `None` (never scored) when **any** of: `--no-evidence`, `--no-redact` (redaction off → source must not reach a third party), no `TYPESAFE_API_KEY`, the `typesafe-sdk` extra absent (function-local import; nothing outside `evidence.py` imports it, the `mcp_server.py` rule), or a dry run. `telemetry_render.py::evidence_summary` renders it into the same `> **Run telemetry.**` line and the CLI's `Evidence:` line. See ADR-014.

**Module importance** (`evidence.score_importance` + `ModuleDescription.role`/`degree`, ADR-015) ranks modules by how load-bearing they are, and — unlike the telemetry fields above — enriches the **graph** itself, not `meta`. Each module carries **two raw components**, filled locally after pass 2 (never LLM-emitted, so NOT in the pass-2 instruction block): `role` (a TypeSafe/Jev **Score** over a leaf→orchestrator ladder, 0–3, the probability-weighted level — `criteria` is an ordered *list*, legend keys `[0,1,2,3]`) and `degree` (in+out import degree from `deterministic_edges` via `evidence.file_degree` — file-level, distinct from `mermaid`'s dir-collapsed degree). They are stored **separate, not pre-fused**: the blend (`_ROLE_WEIGHT 0.6` / `_DEGREE_WEIGHT 0.4` on normalised role + rank-normalised degree) lives in **`render.py::_fused_importance`** so the weighting can be retuned without rewriting `GRAPH.json`, and a reader can audit each signal (the `Faithfulness`/`EvidenceSupport` raw-components precedent). The `## Modules` table gains an **Importance** column and sorts load-bearing first *only* when some module scored; when none did (Jev off), it renders **byte-identical to before** (no column, path sort — pinned by a golden test). `render.py::importance_summary` reads the fused order off `graph.modules` (NOT `meta` — the plan said `meta`, but the data lives on the modules, so this is the better source) for the CLI `Importance:` line. **No `--no-redact` gate** (it sends descriptions + a degree count, never source — gating it would deny importance to `--no-redact` users for no security reason); gated on key + `typesafe` extra + `--no-importance`. `score_importance` **never raises** and `generate_graph` wraps the fill in a second guard — a Jev failure leaves `role`/`degree` `None` (never a fake zero), graph intact. The live divergence proves the fusion earns its place: on a real repo a constants module was import-degree #1 but Jev-role last (a leaf), and a low-degree entry point ranked high — degree alone would mis-rank both. **On a directory-granular graph** (the LLM described `modules` as packages on a large repo — `enrich.is_directory_granular`, most module paths extensionless), the module-level role/degree are too coarse, so importance is instead scored over the **file-level `file_summaries`** (`enrich.score_file_importance`) and stamped into **`meta.file_importance`** (a `list[FileImportance]`, additive-optional, schema stays 1) rather than onto `modules` — `modules` is a diff-compared field and at file granularity there is no graph object that carries importance without a new diff key, so `meta` (not diff-compared, the telemetry precedent) is the right home. `render.py` then emits a `## File Importance` section (absent, hence byte-identical, on file-granular repos), and `importance_summary` prefers `meta.file_importance` over the module fusion. A pre-registered eval measured the fused-vs-degree τ-b gap on argus jump +0.011→+0.105 at file granularity (INNOVATIONS #6, #173's importance counterpart). HTML node-sizing by importance is a deliberate follow-up, not yet built.

**Output destination is a `.graphlm/` subdir of the scanned project, not cwd.** The CLI passes `output_dir=None` into `generate_graph` (so the library doesn't write), then writes via `result.write(output_destination(...))`. `output_destination` (`cli.py`) defaults to `project_dir.resolve() / ".graphlm"` (constant `GRAPHLM_OUTPUT_DIRNAME`) unless `-o` is given — so a symlink checkout still writes after the paid calls (#154); `-o` is honored *literally* (no `.graphlm` appended). This CLI-only default keeps the map out of the project root and inside the scan-excluded `.graphlm/`; the **library** API (`generate_graph(output_dir=...)` / `result.write(dir)`) writes to the literal dir given and is unchanged. This split (fixed in #8) is deliberate — don't "simplify" it by having `generate_graph` write directly.

## Security invariants (don't weaken these)

The scanner treats scanned files as hostile input and has layered defenses — preserve them when editing `scanner.py`/`prompts.py`/`context.py` (and its split-out helpers: `exclusions.py` = `_ALWAYS_EXCLUDE` + `_should_exclude`; `scan_guards.py` = `_symlink_hides_sensitive`/`_is_nested_checkout`/`_path_is_inside`/`load_graphlmignore` — the symlink-escape and nested-checkout guards live there now, #184):
- **Sensitive files are never read** (`_is_sensitive_file`, defined in `redact.py` alongside the never-read extension/name lists and re-imported by `scanner.py`): TLS/key/cert extensions (`.pem/.key/.crt/…`); OpenSSH private-key filenames (`id_rsa`, `id_ed25519`, `id_ecdsa`, and the `_sk` variants — `id_rsa.pub` is not in that set) plus editor/backup names (`id_rsa.bak`, `id_rsa~`, `#id_rsa#`); credential files `.netrc` / `_netrc` / `.pgpass` / `.htpasswd` / `.npmrc` / `.yarnrc` / `.yarnrc.yml` / `.pypirc` and `.flaskenv`, plus their `.bak` / `~` / `#name#` backups; *any* dotenv file — `.env` or a name starting with `.env` (`.envrc`, `.env~`, `.env-local`), plus non-dot forms like `config.env` / `foo.env.local` — except the non-secret templates `.env.example/.sample/.template/.dist` (see `_ENV_SAFE_SUFFIXES`); and name globs (`_SECRET_NAME_PATTERNS`) like `*secret*`/`*secrets*`/`*credentials*`/`*private*`/`*password*`/`*token*`/`*api*key*`/`*auth*key*`. Source extensions (`.py`, `.ts`, …) are exempted from the name globs so `token.py` still gets analyzed.
- **Secret redaction** (`_redact_secrets`, defined in `redact.py` and re-imported by `scanner.py`) runs on every file's content by default (`--no-redact` disables) — regex passes for AWS keys, GitHub tokens, private-key headers, connection strings, JSON `"password"` / `"api_key"` assignments, etc. It runs on the *final* text of a fragment, i.e. **after** skeletonisation/truncation — keep that order (docstring first lines and short constants survive into a skeleton).
- **Nested checkouts are separate projects** (`scan_guards._is_nested_checkout`): any child directory holding a `.git` file (worktree/submodule pointer) or `.git` directory (vendored clone) is skipped in both the tree walk and `os.walk`, so a submodule or an agent worktree under `.claude/worktrees/` never duplicates the map under a second prefix. Only children are tested — the scan root may itself be a repo.
- **Symlink escape prevention** (`scan_guards._path_is_inside`): any symlink (file *or* directory) pointing outside the project is skipped — in the tree walk (so it never appears in the tree or consumes a `max_files` slot) and again before reading content in `os.walk`. In-project *directory* symlinks are also omitted from the tree (matching `os.walk(followlinks=False)`), so a `sub/loop → root` cycle cannot explode the listing and an `alias → pkg` link cannot advertise `alias/mod.py` (#97).
- **Prompt-injection guard**: `SYSTEM_PROMPT` (`prompts.py`) and the pass-2 prompt both instruct the model to treat all file content as data, never instructions. Keep that clause if you touch the prompts.

## Config

LLM settings come from `GRAPHLM_BASE_URL` / `GRAPHLM_API_KEY` / `GRAPHLM_MODEL`, loaded via `python-dotenv` in `config.py::_load_env_files()` (run once at import). **Resolution precedence, highest to lowest, first non-empty wins:** (1) the real shell environment (exported `GRAPHLM_*`); (2) the user-level `~/.config/graphlm/.env` (or `$XDG_CONFIG_HOME/graphlm/.env` when that var is set and non-empty); (3) the built-in defaults. A `.env` in the working directory, any ancestor, or the scanned project is **never** loaded (ADR-009) — those files belong to the target repo, not to graphlm. Precedence is enforced by loading the user file with `load_dotenv(override=False)` so it never clobbers a variable already in `os.environ`; the file is loaded only when it exists (`is_file()`), because `load_dotenv("")` would fall back to a frame-based search from `config.py`'s own directory. CLI flags `-b/-k/-m` override; if you pass any of the three to `generate_graph`, you must pass all three. The context budget resolves `--max-context` flag > `GRAPHLM_MAX_CONTEXT` env var > 120000, the request timeout resolves `--timeout` flag > `GRAPHLM_TIMEOUT` env var > 300s (independently of how the endpoint was configured — passing `-b/-k/-m` must not skip the env, #92), and the output-token budget resolves `--max-output-tokens` flag > `GRAPHLM_MAX_OUTPUT_TOKENS` env var > `LLM_MAX_OUTPUT_TOKENS` (128000, the model's practical max) (all flags and their `generate_graph(...)` params default to `None` so the env var can take effect). **`max_output_tokens` is the `max_tokens` sent in both pass-1 and pass-2 requests — a per-response ceiling, not a reservation.** It is *independent* of `max_context`: input and output ceilings do not share a window on the target endpoint (measured: 180k input + 200k `max_tokens` = 380k combined is accepted — #25), so it is NOT subtracted from the input budget. A high default is therefore free (the model stops when done) and prevents truncating either response; truncation past even it raises a clear `GraphLLErrorTruncated`. The default is sourced once from `llm.LLM_MAX_OUTPUT_TOKENS` (imported by `config.py`). NB: some other OpenAI-compatible servers (vLLM `max_model_len`, Anthropic) *do* bound prompt+generation together — lower the flag on such an endpoint. The 300s default is generous because **pass 2 is streamed** (`llm.py` sends `stream: true` plus `stream_options: {include_usage: true}` and reassembles SSE deltas; the usage option makes a compliant server append one final chunk with empty `choices` and the real token counts, which `_read_streamed_completion` reads *before* its empty-choices skip and returns in a `StreamResult` — an endpoint that ignores the option just yields `usage=None`) — a large project's full-graph generation can take minutes, and streaming keeps it alive past proxy read-timeouts (a non-streamed pass 2 hit a Cloudflare 524 at ~125s, #18). **Pass 2 also sends `response_format: {type: json_schema}`** (derived from `CodebaseGraph.model_json_schema()`, gated on `call_llm(response_format=...)` being set, so pass 1's free-form file-list request omits it) — prompt-only instruction was not enough for every served model, and `Qwen3.6-35B` returned a near-empty `{"database_schema": null}` and produced no graph without the constraint (#31). The endpoint treats the schema as a guided-JSON hint (not strict all-required enforcement), so the prompt's "return an empty `directory_tree`" and the locally-filled `meta`/`import_cycles`/`deterministic_edges` still come back empty — #18 is not reopened. An HTTP **400** (only) triggers a staged fallback: first `stream_options` is dropped (optional telemetry — a strict endpoint that rejects the newer parameter keeps the schema constraint), then, on a second 400, `response_format` is dropped and the request re-issued prompt-only; the two pops plus the final request fit the three attempts. A 401/403/404/429 is not a parameter rejection and still surfaces as an error. `.env.example` shows the shape (URL, key, and model are required placeholders — there are no built-in defaults for those three). `.env` is gitignored — never commit it.

## Tests

`tests/fixtures/{small,medium,large,cyclic,skeleton,ts,java,rust,csharp,ignore}_project/` are realistic sample trees the scanner/parser/cycle tests run against. `ts_project` is the JS/TS pack fixture (relative-import chain, `index.ts` barrel, `.tsx`, a bare `react` import that must be dropped, a 2-node cycle, and a `require()`/dynamic-`import()` file). `java_project` is the Java pack fixture (Maven layout, type import, static import, package wildcard that must be dropped, a 2-node cycle, and a `src/test/java` → `src/main/java` edge). `rust_project` is the Rust pack fixture (`mod` includes, `use crate`/`super`, an external crate that must be dropped, and a cycle). `csharp_project` is the C# pack fixture (unique-file namespace using, `using static`, a multi-file namespace that must be dropped, `using System;` dropped, and a 2-node cycle). `ignore_project` is the `.graphlmignore` fixture. `skeleton_project/big_module.py` is deliberately > 4000 chars with one of every construct the skeleton renderer handles; `tests/test_skeleton.py` pins its exact skeleton as an inline golden string — a renderer change must edit that string. `pyproject.toml` sets `norecursedirs = ["tests/fixtures"]` so pytest doesn't collect them as tests. `tests/test_integration.py` mocks the LLM HTTP call with `pytest-httpx` — no real network. ## CLI flags worth knowing

Beyond the config flags above: `--dry-run` (scan + AST, no LLM), `--json` (also write the machine-readable `GRAPH.json` / `GRAPH_DIFF.json`; **off by default** — the `.md` is the agent-facing map, and graphlm keeps an internal `.graph-state.json` working copy for diff/`--serve` either way), `--no-ast`, `--no-html`, `--no-diff` (skip the `GRAPH_DIFF.*` graph-vs-graph diff), `--no-tests` (real test conventions only — `test_*` / `*_test` / `tests/`; not `latest.py`, #94), `--no-redact`, `--no-skeleton` (send the head of an oversized file instead of its tree-sitter signature skeleton), `--exclude <pat>` (repeatable), `--no-graphlmignore` (skip the project-root `.graphlmignore`; the file is otherwise merged into the exclude set — gitignore-lite, union with `_ALWAYS_EXCLUDE` and `--exclude`; the file itself is always-excluded like `.gitignore`), and the cycle controls `--no-show-cycles` (skip the import-cycle section) / `--cycle-threshold <float>` (only report cycles with risk ≥ threshold). Sizing knobs: `--max-files` (scan cap, default 200), `--max-file-chars` (per-file, 4000 — a longer Python file is skeletonised, not cut), `--max-pass2-files` (files in pass-2 context, 80), `--max-context` (token budget), `--max-output-tokens` (per-pass output ceiling for both LLM calls, default 128000 — a request ceiling, NOT a reserve out of the input budget, see Config above), `--timeout` (LLM request seconds, default 300). Also `-V`/`--version` (eager) and `--upgrade` (short-circuits like `--install-skill`: detect uv-tool/pipx/pip, keep extras, refuse a source checkout; flag not a subcommand, ADR-012). See `graphlm --help` for the full list.

**`--serve`** (`query.py` + `mcp_server.py`) exposes an *existing* map to a coding agent over a stdio MCP server — eight zero-LLM tools (`overview`, `find`, `module`, `neighbors`, `dependents`, `cycles`, `entry_points`, `staleness`). **All logic lives in `query.py`** (pure functions over a `CodebaseGraph`; edges from `deterministic_edges` ∪ `import_edges` merged on `(from, to, kind)` and labelled `ast`/`llm`/`both`; neighbor lists sorted for determinism; `resolve_path` accepts an exact path, a unique `/`-suffix, or a unique extensionless substring (`core` → `app/core.py`) and otherwise returns candidates — a dotted query like `a.py` is not unanchored-substring-matched onto `data.py` (#140)) so it is tested without the SDK; `mcp_server.py` is a thin wrapper over the `mcp` package (**v2 API**: `mcp.server.MCPServer`, tools via `@server.tool()`, anticipated failures raised as `mcp.server.mcpserver.exceptions.ToolError` so the message reaches the model — any other exception is masked by the SDK as a bare "Error executing tool"). The `mcp` package is an **optional extra** (`graphlm[mcp]`, `pyproject.toml`); nothing outside `mcp_server.py` imports it, and CI installs the extra so `tests/test_mcp_server.py` (which drives the real server through the SDK's in-memory `mcp.client.Client`, no subprocess) runs — it `importorskip`s without it. `MapCache` re-reads `GRAPH.json` when its mtime changes, so a regen mid-session is picked up; a missing/corrupt map is a `MapUnavailable` → `ToolError`, never a server crash (`query.load_map` reuses `diff.load_baseline`, checking `UNCOMPARABLE` *before* `FIRST_RUN`). In the CLI, `--serve` short-circuits like `--install-skill` (single-command Typer app — no subcommands, ADR-003): `project_dir` defaults to `.`, the map path is `output_destination(project, -o) / STATE_FILENAME` (the internal working copy `.graph-state.json`, written on every run regardless of `--json`), and the map-exists check runs **before** the `mcp` import so a missing map reports "run `graphlm .`" rather than the install hint. **stdout is the protocol channel** — the server logs to stderr only.

**`--upgrade`** (`upgrade.py`) upgrades this graphlm install to the latest PyPI release and exits. **Same installer as install:** `uv-receipt.toml` → `uv tool upgrade graphlm`; dist-info `INSTALLER=uv` (no receipt) → `uv pip install --python <exe> --upgrade 'graphlm[…]'`; pipx metadata → `pipx upgrade graphlm`; else `python -m pip install --upgrade 'graphlm[…]'`. Extras from the uv receipt or pipx metadata (else probed). Argv list, no shell. A source checkout is refused (exit 2) with the pull/`uv sync` hint. **Do not `Path.resolve()` the interpreter** — uv-tool venvs symlink `bin/python` at a managed CPython *outside* the venv, so resolve walks out of `uv/tools/graphlm` and 0.4.0 then ran `-m pip` in a venv that has no pip (#71). Flag, not a subcommand (ADR-003/012); `project_dir` is unused. Tests inject the runner so CI never hits the network.

**`--setup`** (`setup.py`) is the first-run wizard: it lists the optional extras *not yet installed* (`available_extras` — the seven language packs, `mcp`, `typesafe`; `all` collapses a full language set), takes a numbers/names/`all`/blank selection, and installs the chosen packs with the **same installer** `upgrade.py` detected (`uv tool install --force 'graphlm[…]'` / `uv pip install --python <exe>` / `pipx install --force` / `python -m pip install`) — reusing `upgrade.detect_installer` / `installed_extras` / `_abs_no_follow` / `_spec` (**do not** reinvent them) and the don't-`resolve()`-the-interpreter rule (#71). The install spec is the **union** of already-installed + selected extras, so no existing pack is dropped by the forced reinstall; `_union_extras` collapses the language packs via `_collapse_extras` but **re-appends `typesafe`** because that helper only knows languages/`all`/`mcp` and would otherwise silently drop it. A `typesafe` selection prints the `TYPESAFE_API_KEY` → `~/.config/graphlm/.env` hint. A **source checkout is refused** (points at `uv sync --extra`). `run_setup` **never raises** past its boundary (installer failure → manual-command fallback; detection crash → falls back to `pip`) — a first-run helper must not block the tool. It **writes a completion marker** `~/.config/graphlm/.setup-done` (`marker_path`, XDG-aware like `config._user_config_path`, injectable `home` for tests, **refuses a symlinked marker** #33). The CLI short-circuits on `--setup` (flag, not subcommand, ADR-003) like `--serve`/`--upgrade`; and `_maybe_first_run_setup` auto-runs the wizard once before the first analysis **only when the marker is absent AND stdin is a TTY** — a non-TTY first run prints a one-line `--setup` hint and proceeds, never blocking piped/CI use. `runner`/`prompt`/`which`/`home` are all injectable, so `tests/test_setup.py` drives every installer branch with **no network** (this dev checkout detects as `source`, so a real install never runs in CI). ADR-013. The `typesafe` extra (`graphlm[typesafe]` → `typesafe-sdk`) is **opt-in, not in `[all]`** (commercial third-party API + key); nothing imports it yet — it lands ahead of the prose evidence-scoring feature, so the Commands block above has **no `--extra typesafe` dev-sync line** on purpose (there is no test that needs the SDK until that change adds one; `tests/test_setup.py` uses injected fakes). The auto-trigger writes the completion marker even on a non-TTY run, so a piped/CI first invocation consumes the one-shot hint (deliberate — ADR-013).

**`--install-skill <harness>`** (`skills.py`) installs an agent guide teaching a coding harness to read `.graphlm/GRAPH.md` when it opens a repo (and regenerate with `graphlm .` when missing/stale), then exits. It is **not** an eager callback — instead `project_dir` is an *optional* argument (default `None`) and the command body short-circuits to `_do_install_skill` when `--install-skill` is set, so `graphlm --install-skill claude` runs with no `project_dir`; the analyze path then guards `project_dir is None` with a clean exit-2 message. Harnesses: `claude` → `~/.claude/skills/graphlm/SKILL.md` (real skill frontmatter); `codex` → `~/.codex/graphlm.md` **plus a printed snippet** to paste into the user's own `AGENTS.md` (Codex has no arbitrary-file include — verified; and graphlm never edits a user-owned `AGENTS.md`/`CLAUDE.md`). User-global by default; `--skill-local` writes into the project, `--skill-force` overwrites. `install_skill(..., home=...)` takes an **injectable `home`** (defaults to `Path.home()`) so tests never touch the real `~`. Idempotent (skip-if-exists unless force). It **refuses to write through a symlink** at the target (`is_symlink()` check before write, catches broken links too) so a dotfiles-managed `~/.claude/skills/` isn't clobbered (#33) — the CLI turns that `ValueError` into a clean exit-2.
